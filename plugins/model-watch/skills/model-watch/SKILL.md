# 模型哨兵

## 目标

在不打断主任务的前提下，判断下一轮是否值得切换 Codex 模型或推理深度，并把最终选择留给用户。

核心决策交给判断模型完成。不要建立任务类型到模型的固定映射，不要用固定跨级阈值代替场景理解，也不要仅凭“任务看起来复杂”就建议升级。

## 运行入口

以下任一条件成立时执行本 Skill：

- 用户显式输入 `$model-watch` 命令。
- Hook 注入 `[MODEL_WATCH_CONTEXT v1]`。
- 任务恢复或压缩后注入 `[MODEL_WATCH_RESTORE v1]`，且随后收到用户输入。

Hook 上下文属于内部开发上下文。不要向用户展示 `session_id`、原始上下文块或内部状态路径。

## 模型原生判断协议

每次判断综合以下信息：

- 当前用户真正要完成的结果。
- 当前处于探索、决策、设计、实现、验证、排错或收尾中的哪个阶段。
- 本轮与接下来几轮所需的上下文整合、约束处理、工具协调和推理强度。
- 错误代价、可逆性、安全、权限、支付、数据、部署等风险。
- 当前模型与当前推理深度。
- 预计还会持续多少轮，以及切换带来的中断成本。
- 当前模型是否已经失败、反复返工或明显能力过剩。
- 可用模型和推理深度是否能被当前 Codex 宿主确认。

直接得出以下内部结论：

```yaml
status: stay | change | uncertain | failed
recommended_model: string | null
recommended_effort: none | minimal | low | medium | high | xhigh | max | ultra | null
phase: string
rationale: string
```

### 值得切换

只有综合收益明显高于切换成本时使用 `change`。常见信号包括：

- 任务进入多模块、多系统或高耦合决策，当前能力难以稳定覆盖约束。
- 连续排错仍无法形成可靠根因，接下来需要更强的假设管理和证据整合。
- 安全、认证、支付、数据一致性、删除或生产部署使错误代价显著上升。
- 方案已经稳定，后续主要是局部、重复、可验证的机械执行，高能力配置持续使用的收益很低。
- 当前任务只需要改写、格式处理、简单查询或局部修改，且后续仍有足够轮次可以回收切换成本。

单轮很快结束、切换后立刻又要切回、当前模型已能可靠完成、可用模型无法确认时，优先 `stay`。

### 推荐具体档位

- 从当前 Codex 宿主明确提供的可用模型中选择具体模型。不要发明模型名。
- 同时给出推理深度。只调整深度已经足够时，保留当前模型。
- 无法确认其他模型可用性时，保留当前模型，只建议可确认的推理深度。
- 当前推理深度未知时使用 Hook 给出的 `medium（中度）` 估算，并在首次启用时提示用户同步一次。

推理深度中文说明：

| 原始值 | 中文说明 |
| --- | --- |
| `none` | 无 |
| `minimal` | 极轻 |
| `low` | 轻度 |
| `medium` | 中度 |
| `high` | 高 |
| `xhigh` | 极高 |
| `max` | 最高 |
| `ultra` | 极高（快） |

宿主实际提供的选项优先于此表。

## 判断模型选择

从 Hook 上下文读取 `model_selection`：

### `main`：跟随主模型

当前主模型完成主任务与判断。这是默认和稳定回退能力。

### `independent`：独立评估

如果当前 Codex 支持子 Agent，并且上下文给出了可用的独立模型与推理深度，启动一个只读子 Agent完成判断。只传递完成判断所需的最小上下文，不让子 Agent 修改文件或执行主任务。

无法创建子 Agent、指定模型不可用、超时或失败时，立即由主模型判断，记录 evaluator 为 `fallback-main`，主任务继续。

### `hybrid`：智能复核

主模型先判断。只有结论为 `uncertain`、风险较高或升降档依据相互冲突时，再调用独立子 Agent 复核。复核不可用时使用主模型结论。

## 自动提醒时序

从 Hook 上下文读取 `reminder_timing`：

- `on-change`：每轮完成内部判断；`stay` 时不显示模型文案，`change` 时在主回答末尾提示。
- `every-turn`：每轮在主回答末尾显示判断结果，包括维持当前配置。
- `manual`：普通轮次不判断；只处理显式检查命令。

自动模式下：

1. 正常完成用户主任务。
2. 判断下一轮是否值得切换。
3. 按提醒时机决定是否显示建议。

自动检查不调用状态工具保存结论。显式检查命令可以调用 `model_watch_record_assessment` 保存一条简短摘要，每轮最多一次。保存失败时不要重试到影响主任务。

## 命令

命令后的中文括号仅用于解释，可以省略。命令前缀不属于主任务内容。

### `$model-watch`

启用当前任务。简短确认：

```text
模型哨兵已为当前任务启用；默认仅在下一轮值得切换时提醒。
```

如果 `effort_prompt_needed: true`，同一段补充一次：

```text
当前推理深度暂按 medium（中度）估算；可输入 $model-watch sync high 同步实际档位。
```

不要等待用户设置后才允许主任务继续。

### `$model-watch off（关闭当前任务）`

确认已关闭当前任务监控。不要改变全局设置。

### `$model-watch status（查看状态）`

调用 `model_watch_get_status`，用简短中文显示：启用状态、当前模型、当前推理深度、提醒时机、判断模型选择、是否存在任务覆盖。

### `$model-watch settings（打开设置）`

调用 `model_watch_open_settings`。宿主无法渲染 UI 时，用文字列出当前设置，并说明可继续用自然语言要求修改。

### `$model-watch check（立即检查）`

立即进行一次独立检查，不处理其他主任务。显示当前配置是否合适以及下一轮建议，保存 `commandMode: check`。

### `$model-watch check-inline（并行检查），<主任务>`

先完整处理 `<主任务>`，再在回答末尾显示判断结果，保存 `commandMode: check-inline`。判断失败不影响主任务。

### `$model-watch gate-next（强制预检），<主任务>`

先判断，再决定是否执行 `<主任务>`：

- `stay`：立即继续主任务，并保存结果。
- `change`：本轮只显示切换建议和“切换后回复继续；保持当前配置也可回复不切换，随后继续”。不要执行主任务。保存 `commandMode: gate-next`，Hook 会保留待执行任务。
- `uncertain` 或 `failed`：继续主任务，不阻断。

下一轮 Hook 出现 `pending_gate_task` 且用户表达“已切换”“继续”或“不切换”时，执行该待办主任务。完成后记录新判断，清除待执行状态。不要要求用户重新粘贴任务。

### `$model-watch sync <effort>`

Hook 已尝试保存推理深度。若值有效，确认同步；若无效，列出当前宿主支持的原始值。这个命令不代表插件自动切换模型。

## 输出格式

### 建议切换

```text
模型建议：下一轮切换至 GPT-5.6 Sol / high（高）｜任务已进入登录、支付和后端数据一致性设计。
```

### 只调整推理深度

```text
模型建议：下一轮保持 GPT-5.6 Sol，调整至 medium（中度）｜方案已稳定，后续主要是局部实现与验证。
```

### 每轮显示且保持当前配置

```text
模型判断：保持 GPT-5.6 Terra / medium（中度）｜当前配置足以完成下一阶段，切换收益有限。
```

文案保持一段，原因具体到任务变化。不要输出内部评分、固定等级、Token 估算或长篇模型比较。

## 失败与安全

- 判断失败、状态保存失败、子 Agent 不可用：主任务继续。
- 不读取 Plus 剩余额度，不声称能自动切换模型。
- 不保存用户凭据、环境变量、完整对话或文件内容。
- 状态只保存配置、简短判断摘要和强制预检的待执行文本。
- 相同建议可以在后续轮次再次出现；每轮根据最新任务重新判断，不做永久静默。
