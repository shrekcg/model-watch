# 模型哨兵

`模型哨兵` 用于连续任务中的**下一步模型选择**。它复用当前主 Agent 的模型，结合已发生的对话、本轮请求和切换成本判断：继续使用当前模型，还是先建议你换一个模型。

默认关闭。只有你在某个任务中主动启用后才会工作，因此不会为不需要的任务增加判断成本。

## 你会得到什么

- **不打断普通任务**：模型仍适合时，内部完成判断后直接交付任务结果。
- **需要切换才暂停**：只有切换收益明确时，才展示模型建议和原因，不继续执行本轮主任务。
- **模型由你选**：你可以采纳建议、保持当前模型，或选择其他模型；插件不会替你操作 Codex 的模型选择器。
- **续跑不重复判断**：选择完成后原样重新发送同一请求，插件直接执行，并记录实际选择结果。
- **可回溯最近决策**：本地保留最近 12 条评估及实际选择记录，关联建议 ID、模型与时间，不保留任务正文或附件。

一期只包含当前主 Agent 的同会话判断；没有子 Agent 评估器、外部评估服务、自动切模型或推理深度切换。

## 一次完整体验

<p align="center">
  <img src="./assets/readme/workflow.svg" width="100%" alt="模型哨兵工作流：启用后，真实请求进入内部判断；合适时直接执行，需要切换时展示建议，用户选择模型后原样重发并继续任务">
</p>

1. 在目标任务中发送 `!model-watch on`。这是一条开关命令，不执行评估。
2. 启用后的下一条真实请求会进入内部判断。第一轮通常用于完成任务并建立连续上下文。
3. 后续请求中，当前模型仍合适就直接执行；若建议切换，本轮只展示建议和理由。
4. 你在 Codex 原生模型选择器中选择任意模型，然后原样重新发送这条请求。
5. 插件识别为已判断请求，直接执行主任务，并在下一次交互中观察你的实际选择。

> 这是“同会话逻辑拦截”，不是模型调用前的硬 Hook 阻断：本轮请求已经进入当前主模型，由它先完成判断并遵守协议。因此会消耗一次判断成本；如果模型没有遵守协议，插件无法撤销已经开始的主任务。

## 场景示例：从正常推进到人工切换

<p align="center">
  <img src="./assets/readme/examples.svg" width="100%" alt="两轮连续任务示例：第一轮正常完成架构草图，第二轮高风险支付审计触发模型建议，用户选择后原样重发并继续">
</p>

```text
第一轮：设计订阅支付系统的基础架构
结果：正常完成架构草图。模型哨兵在内部完成判断，不展示判断过程。

第二轮：在不改文件的前提下，审计支付、退款、账本、消息队列和回滚风险
结果：如果当前模型不再合适，只显示：

模型建议：切换至 GPT-5.6 Sol
原因：本轮涉及生产支付决策、跨服务一致性与可验证的风险审计。
```

随后你可保持当前模型，或选择建议模型/其他模型；原样重发第二轮请求后，才开始执行审计主任务。建议来自当时的上下文，不是“任务类型 → 模型”的固定映射，因此不承诺任何一句输入必然触发切换。

## 安装与首次启用

### 1. 安装并信任 Hook

需要支持 Plugins、Hooks 与 MCP Apps 的 Codex，以及 Node.js 20+。

```bash
codex plugin marketplace add https://github.com/shrekcg/model-watch.git
codex plugin add model-watch@model-watch
```

完整重启 Codex，在插件管理页批准 `SessionStart` 和 `UserPromptSubmit` Hook。然后从 `/` 菜单选择“模型哨兵”，在需要监测的任务中发送：

```text
!model-watch on
```

看到启用确认后，再发送真实任务。仅选中 `/` 菜单里的插件不会自动开启监测。

### 2. 只在需要的任务中开启

| 方式 | 作用 |
| --- | --- |
| `!model-watch on` | 启用当前任务；推荐入口 |
| `!model-watch off` | 关闭当前任务，不影响其他任务 |
| `!model-watch pause` | 暂停判断，主任务照常执行 |
| `!model-watch resume` | 恢复当前任务的判断 |
| `!model-watch settings` | 打开设置界面 |
| `!model-watch check` | 只做一次检查，不执行主任务 |
| `!model-watch check-inline，<主任务>` | 主动检查；适合验证流程 |

`$model-watch` 仍是兼容别名，但可能触发宿主的插件补全；按需启用请优先使用 `!model-watch on`。`/hooks` 可用于检查 Hook 信任状态。

控制命令请单独发送。若把 `!model-watch on`、暂停、设置等命令和任务正文写在同一条消息中，插件只处理命令，并提示你在下一条消息重新发送任务正文，避免静默丢失请求。

## 候选模型

一期的默认候选集是 `gpt-5.6-luna`、`gpt-5.6-terra`、`gpt-5.6-sol`。它是插件当前可验证的判断约束，并不是 Codex 宿主动态返回的模型列表；`change` 只有推荐到该列表中、且不同于当前模型的模型时才会生效。

在本地开发或自行管理插件进程的环境中，可在启动 Codex 前设置 `MODEL_WATCH_AVAILABLE_MODELS` 覆盖候选集：

```bash
export MODEL_WATCH_AVAILABLE_MODELS="gpt-5.6-luna,gpt-5.6-terra,gpt-5.6-sol"
```

如果桌面端实际可选模型与该列表不一致，插件会安全地把无效 `change` 降级为正常执行，不应把它视为可完成自动切换的配置。宿主模型列表的动态读取是后续能力，不在一期范围。

## 设置界面

<p align="center">
  <img src="./assets/readme/settings.svg" width="100%" alt="模型哨兵设置：全局默认控制新任务自动启用，当前任务可单独启用或暂停；运行标识仅是可选反馈，不改变判断流程">
</p>

设置分为两层：

- **全局默认**：新任务是否自动启用（默认关闭），以及是否显示可选的运行反馈。
- **当前任务**：只影响正在打开的对话，可启用、关闭或暂停；启用后固定对每条真实请求进行内部判断。

设置界面只有拿到精确任务 ID 时才会保存当前任务配置。没有任务 ID 时只能保存全局默认，不会误改最近打开的另一个任务。

## 产品边界与可靠性

```text
UserPromptSubmit Hook
  → 读取当前任务状态、当前模型与请求指纹
  → 向当前主 Agent 注入内部判断协议
  → 通过 MCP 保存判断结果
  → change 时等待用户在原生界面选择模型并原样重发
  → 指纹命中后直接执行，并观察实际模型
```

- Hook 不会调用独立模型或外部 API；评估器固定为当前主 Agent 的同会话模型。
- MCP 使用官方 SDK；保存时校验精确会话、当前模型和候选模型，拒绝“建议切换到当前模型”这类无效建议。
- 状态写入采用原子写和带 PID、随机令牌的文件锁，避免多任务并发时串写或误删锁。评估结果必须绑定 Hook 提供的精确 `turnId`；迟到结果会安全拒绝，不会覆盖下一条请求。
- 状态只保存配置、模型元数据、请求 SHA-256 指纹、最近 12 条评估与观察结果；**不保存任务正文或附件**。观察结果会关联当时的评估 ID，包含采纳、保持、其他模型、被新请求替代、超时或关闭。请求指纹不能用于恢复原文，低熵短文本仍可能被猜测，因此不是加密保险箱。
- 严格 JSON、纯代码和其他机器可读结果不会插入可见状态文案，以免破坏解析。

## 需要知道的限制

- Hook 必须被信任；拒绝后，评估注入、续跑识别和完整状态闭环不会工作。
- 老任务不一定热加载新安装的插件能力；优先新建任务，或使用 Codex 的 Fork 保留历史后验证。
- 建议出现后，附件能否方便地原样重发取决于 Codex 桌面端；插件本身不保存或重放附件。
- 设置页展示的是最近有限历史，不是长期行为分析仓库；超过 12 条的旧记录会被滚动清理。
- 运行标识是可关闭的辅助反馈，不属于模型选择工作流。
- 推荐准确度和切换阈值仍需通过真实任务持续校准。

## 本地开发与验证

插件 MCP 依赖官方 `@modelcontextprotocol/sdk` 与 `zod`；运行依赖不提交到 Git。克隆仓库后：

```bash
npm ci
npm ci --prefix plugins/model-watch
npm test
git diff --check
```

更新本地已安装插件：

```bash
npm run update:plugin -- --no-refresh
```

自动测试覆盖命令解析、协议、状态迁移、精确会话隔离、并发锁、MCP 设置页和同一请求续跑。真实桌面端请按 [中文手工测试用例](./docs/manual-test-cases.md) 验证 Hook 信任、插件热加载、普通执行、建议切换与设置同步。
