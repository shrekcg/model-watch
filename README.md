## 模型哨兵能做什么

模型哨兵为 Codex 长任务提供持续的模型配置决策：它结合任务阶段、风险、预计轮次与切换成本，判断下一轮是否值得调整模型或推理深度。当前配置合适时保持静默，主任务照常进行。

```text
模型建议：下一轮切换至 GPT-5.6 Sol / high（高）｜任务已进入登录、支付和后端数据一致性设计。
```

- 同时推荐具体模型和推理深度。
- 默认仅在切换具有明确收益时提醒。
- 支持自动监控、立即检查、并行检查与强制预检。
- 支持全局默认和当前任务覆盖。
- 可视化设置不可用时保留完整文字命令。
- 任务恢复、长对话压缩后重新加载监控状态。

## 核心：模型原生判断引擎

“是否值得切换模型”的决策直接交给判断模型完成。

判断模型读取当前任务、项目阶段、约束、风险、失败证据、预计剩余轮次、当前配置和切换成本，直接给出推荐模型、推理深度与理由。程序负责组织输入、校验结果、保存状态、控制提醒时机和失败回退。

固定任务映射、固定能力等级和跨级阈值不会参与核心决策。这样做有三个好处：

1. 同一套机制可覆盖开发、产品、研究、写作、设计和故障诊断。
2. 主模型的场景理解能力升级后，判断质量也能随之提升。
3. 判断协议与执行模型解耦，未来可接入更小的专用判断模型。

## 实践示例

<p align="center">
  <img src="./assets/readme/examples.svg" width="100%" alt="模型哨兵在保持静默、调整推理深度、降低档位和提高档位时的输出示例">
</p>

```text
模型判断：保持 GPT-5.6 Terra / medium（中度）｜当前配置足以完成下一阶段，切换收益有限。

模型建议：下一轮保持 GPT-5.6 Sol，调整至 medium（中度）｜方案已稳定，后续主要是局部实现与验证。

模型建议：下一轮切换至 GPT-5.6 Luna / low（轻度）｜剩余工作是多轮格式整理和局部替换。
```

同一类动作可能得到不同结论。判断会考虑风险、上下文负担、预计持续轮次，以及切换后是否很快又要切回。

## 工作流

<p align="center">
  <img src="./assets/readme/workflow.svg" width="100%" alt="模型哨兵自动监控下一轮模型配置的工作流">
</p>

1. Hook 在用户输入前读取当前模型、任务状态与生效配置。
2. Hook 注入精简判断上下文；普通任务不会加载整份 Skill 文档。
3. 主模型完成本轮任务，并评估下一轮配置。
4. 当前配置合适时不增加可见文案；值得切换时追加一行建议。
5. Hook 与本地状态层保留配置和预检待办，供下一轮、任务恢复和压缩恢复使用。

判断或状态保存失败时，本轮主任务继续。

## 安装

需要支持 Plugins 与 Hooks 的 Codex 环境，以及 Node.js 20 或更高版本。仓库不需要安装第三方运行依赖。

```bash
codex plugin marketplace add shrekcg/model-watch
codex plugin add model-watch@model-watch
```

安装后重启 Codex，按提示审阅并信任插件 Hook。官方插件机制会在新任务中加载已安装的 Skill、Hook 与 MCP 工具；完整说明见 [OpenAI Plugins](https://learn.chatgpt.com/docs/plugins) 和 [Hooks](https://learn.chatgpt.com/docs/hooks)。

新任务默认不会自动启用。在任务中输入：

```text
$model-watch
```

## 在安装前已经存在的旧任务中启用

旧任务兼容链路已经包含在插件中：`SessionStart(resume)` 负责恢复插件状态，`UserPromptSubmit` 负责接收启用命令。

优先使用无 Fork 路径：

1. 安装插件并重启 Codex。
2. 重新打开原来的旧任务。
3. 输入 `$model-watch`。
4. 看到“模型哨兵已为当前任务启用”后继续原对话。

首次无法识别推理深度时，插件按 `medium（中度）` 估算，并提示一次同步命令：

```text
$model-watch sync high
```

部分旧版客户端只在新任务边界加载新安装的插件。如果旧任务中输入 `$model-watch` 后没有启用确认，或设置工具不可用，说明该任务没有加载插件能力。此时使用 **Fork 任务**作为兜底，在 Fork 后输入 `$model-watch`；原任务上下文会随 Fork 保留。

## 设置与默认值

<p align="center">
  <img src="./assets/readme/settings.svg" width="100%" alt="模型哨兵的全局默认和当前任务设置界面">
</p>

输入 `$model-watch settings` 打开设置卡片。当前宿主不渲染 MCP Apps UI 时，Codex 会改用文字显示和自然语言配置。

| 设置项 | 默认值 | 可选项 |
| --- | --- | --- |
| 新任务自动启用 | 关闭 | 开启 / 关闭 |
| 提醒时机 | 仅需要切换时提醒 | 仅变化时 / 每轮显示 / 手动检查 |
| 模型选择 | 跟随主模型 | 跟随主模型 / 独立评估 / 智能复核 |
| 独立判断模型 | 未设置 | 宿主可用的子 Agent 模型与推理深度 |
| 当前任务配置 | 跟随全局 | 跟随全局 / 单独覆盖 / 暂停 / 关闭 |

### 判断环节使用哪个模型

| 模型选择 | 运行方式 | 失败回退 |
| --- | --- | --- |
| 跟随主模型 | 当前主模型同时完成任务与判断 | 无额外模型调用 |
| 独立评估 | 指定 Codex 子 Agent 只读评估 | 回退主模型 |
| 智能复核 | 主模型先判断，仅在不确定或高风险时复核 | 回退主模型 |

## 命令速查

```text
$model-watch                         启用当前任务
$model-watch off（关闭当前任务）
$model-watch status（查看状态）
$model-watch settings（打开设置）
$model-watch check（立即检查）
$model-watch check-inline（并行检查），<主任务>
$model-watch gate-next（强制预检），<主任务>
$model-watch sync high（同步推理深度）
```

`gate-next` 会先判断配置。需要切换时先停在建议处，用户选择切换或保持当前配置后，插件继续保存的待执行任务，无需重新粘贴。

## 额外额度开销

自动监控会增加少量上下文；显式设置与预检会调用本地状态工具，独立评估会额外启动子 Agent。以下数字是工程预算，实际值受模型、缓存、上下文和宿主实现影响：

| 模式 | 单次检查额外预算 | 说明 |
| --- | ---: | --- |
| 未启用 / 手动未触发 | 约 0 模型 Token | Hook 本地退出 |
| 跟随主模型 | 约 250–700 Token | 精简 Hook 上下文与判断摘要；普通自动轮次不调用状态工具 |
| 显式命令轮次 | 在上项基础上增加约 1,500–4,000 Token | 需要加载完整 Skill 指令 |
| 独立评估 | 额外约 800–2,500 Token + 子 Agent 推理 | 增加一次模型执行 |
| 智能复核 | 通常接近跟随主模型 | 触发复核时叠加独立评估开销 |

只想偶尔判断时可选择“手动检查”。Plus 剩余额度无法直接换算成上述 Token，插件也不会读取账户实时余额。

## 架构与本地数据

| 组件 | 职责 |
| --- | --- |
| Skill | 显式命令、判断协议和输出格式 |
| Hook | 启用、每轮注入、旧任务与压缩恢复 |
| 模型原生判断引擎 | 结合场景直接决定是否值得切换 |
| 状态层 | 保存全局配置、任务覆盖、显式检查摘要和预检待办 |
| MCP Server + UI | 设置、状态、判断记录和中文设置卡片 |

- 数据写入 Codex 提供的插件数据目录。
- 不采集遥测，不接入外部 AI 服务，不保存 API Key、Token 或完整对话。
- 强制预检只暂存继续任务所需的文字，完成后由后续判断清理。

## 边界

- 插件给出下一轮建议，模型与推理深度仍由用户切换。
- Hook 能稳定读取当前模型；推理深度由用户同步，未同步时默认按中度估算。
- 独立评估依赖当前 Codex 宿主的子 Agent 和模型可用性。
- Hook 必须经过用户信任；禁用 Hook 后自动监控与旧任务恢复不会运行。
- 已打开的旧任务能否热加载新插件由客户端版本决定，因此保留 Fork 兜底。
