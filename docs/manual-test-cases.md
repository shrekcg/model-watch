# 模型哨兵 1.1.1 本地手工测试

本轮验收同会话默认路径、确定性建议卡测试，以及自定义评估模型。内部子 Agent、外部 API、自动切换与发布均不在范围内。

## 完成标准

- 手动启用后，下一条真实请求开始评估。
- 开启全局自动启用后，新任务第一条真实请求开始评估。
- 启用期间每条真实请求都产生并保存一次判断。
- 普通 `stay` 先在内部完成判断，再静默执行主任务；不显示分析、判断或 stay 文案，只显示 `🛰️`。
- `change` 不执行主任务，只显示两行建议；重新发送同一请求后直接执行。
- 暂停、恢复、关闭和失败放行符合预期。

## 测试前检查

1. `codex plugin list` 中 `model-watch@model-watch` 为 `installed, enabled`，版本为 `1.1.1`（本地更新脚本可能附加 Codex 缓存后缀）。
2. `codex mcp list` 中 `model-watch` 为 `enabled`。
3. 完整重启 Codex，并在插件管理页批准 `SessionStart` 与 `UserPromptSubmit` Hook。
4. 新建一个测试任务，避免旧任务未热加载 Skill 或 MCP 工具。
5. 需要稳定复现时，使用 [确定性测试夹具](./testing-fixtures.md)，不要依赖真实引擎恰好输出某个结果。

## P0：核心链路

| 编号 | 场景 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| P0-01 | 首次启用 | 在要监测的新任务发送 `!model-watch on` | 只确认已启用；本轮不评估；末尾显示 `🛰️` |
| P0-02 | 启用后第一次请求 | 发送“把这句话改成更简洁的中文：我们现在开始执行” | 引擎先在内部完成判断；主任务完成；不显示分析、判断或 stay 文案；末尾显示 `🛰️`；状态中保存本轮 `stay` |
| P0-03 | 后续每轮评估 | 连续发送两个不同的简单整理请求 | 两次都完成主任务；最近判断时间随每轮更新；没有多余 stay 文案 |
| P0-04 | 主动检查 | 发送 `!model-watch check` | 只显示当前模型是否保持及一句原因，不执行其他任务 |
| P0-05 | 切换建议 | 在较轻模型中发送一个确实需要更强模型的连续任务 | 主任务不执行；只显示两行模型建议与原因；第一行末尾显示 `🛰️` |
| P0-06 | 切换后重发 | 切换到推荐模型，原样重新发送 P0-05 请求 | 不重复评估，直接执行原任务；状态记录为采用建议 |
| P0-07 | 保持后重发 | 再次触发建议，保持当前模型并原样重发 | 不重复评估，直接执行原任务；状态记录为保持原模型 |
| P0-08 | 改成新请求 | 触发建议后发送不同内容 | 旧建议标记为被新请求替代；新请求重新评估 |
| P0-09 | 确定性建议卡 | 已启用任务单独发送 `!model-watch test-card` | 必定显示“确定性测试”建议卡；不执行主任务；不依赖模型判断 |
| P0-10 | 测试卡续跑 | 在 P0-09 卡片前切换或保持模型，再点击任一按钮 | 同一任务只续跑一次；显示测试完成标记；实际模型按 Hook 记录；测试记录不出现在真实历史摘要 |

P0-05 是否触发 `change` 取决于模型原生判断。若没有触发，不要使用固定关键词强迫结果；改用一个在当前上下文中切换净收益更明确的真实任务。

## P1：状态与配置

| 编号 | 场景 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| P1-01 | 新任务默认关闭 | 保持“新任务自动启用”关闭并新建任务 | 普通请求不运行哨兵，不显示 `🛰️` |
| P1-02 | 新任务自动启用 | 打开“新任务自动启用”并新建任务 | 第一条真实请求直接评估并显示 `🛰️` |
| P1-03 | 暂停 | 发送 `!model-watch pause` 后发送普通任务 | 普通任务直接完成，不做模型判断，末尾显示 `🛰️⏸️` |
| P1-04 | 恢复 | 发送 `!model-watch resume` 后发送普通任务 | 下一条真实请求恢复评估，末尾显示 `🛰️` |
| P1-05 | 关闭 | 发送 `!model-watch off` 后继续对话 | 不再评估，不显示状态标识 |
| P1-06 | 标识关闭 | 关闭“显示运行标识”后发送普通任务 | 仍完成并保存判断，但回复末尾不显示 `🛰️` |
| P1-07 | 压缩与重开 | 触发压缩或重新打开任务 | 启用、暂停和标识设置保持一致 |
| P1-08 | 多任务设置隔离 | 在任务 A 打开设置后，切换到任务 B 再保存 B 的设置 | B 只更新 B；若设置卡片没有精确任务 ID，只允许保存全局设置，不得修改最近任务 |
| P1-09 | 暂停后的主动检查 | 暂停后发送 `!model-watch check-inline，整理这段文案` | 不做判断或建议，直接执行逗号后的主任务 |
| P1-10 | 建议关闭记录 | 触发 `change` 后发送 `!model-watch off` | 旧建议被标记为“已关闭”，而不是静默消失；设置页可见最近记录数量 |
| P1-11 | 历史回溯 | 连续完成一次 `change → 重发` | 设置页最近判断保留理由与模型；实际选择记录关联同一建议；不显示请求正文或附件 |
| P1-12 | 自定义评估模型 | 打开设置、刷新目录 | 评估方式默认“跟随主模型”；选择“自定义评估模型”后，下拉可选择当前目录中的模型 |
| P1-13 | 自定义评估模型执行 | 选择任一目录模型，保存后发送简单任务 | 正常完成；设置历史可见实际 evaluatorModel、contextCoverage 为 current-input-only；无法调用/超时时先记录一次失败，再记录同会话回退，主任务仍完成 |
| P1-14 | 评估记录与成本 | 打开设置页“评估记录”，完成一次测试卡、一次同会话判断和一次自定义评估 | 可查看当前任务最近 12 条真实/测试记录及实际选择；每条显示实际/请求评估器、耗时、回退和原因；自定义评估成功显示 API 等价粗估成本，同会话或失败显示 `—`；不显示正文或附件 |

## P2：失败与边界

| 编号 | 场景 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| P2-01 | MCP 工具缺失 | 在未热加载 MCP 的旧任务尝试启用 | 明确提示新任务或 Fork；不声称恢复识别已生效 |
| P2-02 | 判断不确定 | 使用上下文不足、候选模型不明确的请求 | 主任务继续，不阻断 |
| P2-03 | 机器可读输出 | 要求只返回严格 JSON 或纯代码 | 不追加 `🛰️`，保证输出可解析 |
| P2-04 | 请求正文隐私 | 检查本地任务状态 | 只存在 SHA-256 和模型元数据，不保存任务正文 |
| P2-05 | 命令与正文混发 | 发送 `!model-watch on，整理这段文案` | 只启用任务，明确提示正文未执行、需下一条重新发送；不得静默丢失或误执行 |
| P2-06 | 候选模型可用性 | 确认当前桌面端可选模型与插件候选集一致，再触发 change | 只建议实际可选且不同于当前模型的候选；不一致时安全失败放行 |
| P2-07 | Hook/MCP 状态一致 | 启用任务、打开设置、触发一条普通请求后交叉查看状态 | Hook、设置卡片和 MCP 状态显示同一任务的启用与最近判断，不出现状态分裂 |
| P2-08 | 迟到评估结果 | 在新请求已经提交后，让上一轮评估工具迟到返回 | MCP 明确拒绝旧 `turnId` 的结果，不覆盖新请求的判断或路由票据 |
| P2-09 | 目录过期或刷新失败 | 等待目录快照超过 1 小时，或在离线环境点击刷新 | 保留上一次快照供查看，但候选安全回退为内置 GPT；不把旧目录或未知额度当成外部模型可用性 |

## 已知边界

- 同会话路径属于逻辑拦截，不是模型调用前的硬 Hook 阻断。
- `🛰️` 由模型按 Hook 指令追加，不是 Codex 原生常驻图标。
- 切换建议后需要原样重新发送请求；当前本地状态不保存、重放或恢复任务正文与附件。
- 路由匹配使用同会话内的文本 SHA-256 指纹；由于宿主未提供稳定附件指纹，不能把它宣称为附件的字节级重放或保真保证。
- 自定义评估模型会产生独立本地 Codex 调用，只看到本轮输入；不能宣称完整历史、附件或工具结果无损继承，失败或超时会回退同会话判断。
- “API 等价成本”仅用公开 API 标价对可见评估包和固定输出 token 假设做粗估，不是 Codex 订阅或账户的实际扣费。自定义评估未完成、同会话评估均不显示虚构成本。
